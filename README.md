# astrbot_plugin_no_reply · 不予回复

AstrBot 的多检测词沉默插件，适用于 **AstrBot 4.29 及后续 4.x 的标准 AI 文本回复链路**。
支持流式输出，默认检测 `[NO_REPLY]`，默认只检查开头 **32 字符 / 32 分片**。不修改 AstrBot 或平台适配器的源文件，无额外运行时依赖。

## 安装

1. 先停用原有 `astrbot_plugin_silent_response` 等同类插件，避免重复注入、重复处理会话历史。
2. AstrBot → 插件 → 安装插件 → URL 安装，填写：
   `https://github.com/Lvara1024/astrbot_plugin_no_reply`
3. 确认对应平台当前使用的配置文件启用了本插件。
4. 保持 AstrBot 的流式输出开启。默认设置即可使用；修改插件配置后保存并重载插件。

也可下载仓库 ZIP，通过“上传文件”安装。

**从 v1.0.0 升级：**已有配置不会被默认值覆盖，请手动把 `max_buffer_chars` 和 `max_buffer_chunks` 都改成 `32`。v1.1.0 超出识别窗口后放行，不再丢弃普通长回复。

## 平台支持

插件在平台适配器之前处理 AstrBot 的通用消息事件，**不设平台白名单**。QQ（NapCat / OneBot、官方机器人）、飞书、Telegram、Discord、钉钉、企业微信、Slack、WebChat，以及其他遵循标准事件接口的适配器，均使用同一套逻辑。

| 发送方式 | 处理方式 |
|---|---|
| 非流式回复 | 在模型回复和最终消息装饰钩子中检测，发送前拦截 |
| 平台原生流式回复 | 在 `event.send_streaming()` 消费分片之前检测，再交还原适配器发送 |
| 平台将流式回退为普通消息 | 仍先经过同一个过滤器，保留原平台的回退行为 |
| 飞书流式卡片 | 命中时不创建卡片；正常回复保留更新、工具分段和关闭卡片的行为 |
| WebChat | 命中时不发送文本，但保留空的结束通知，让界面正常退出生成状态 |

通用接口兼容不等于每个平台都已实机测试。当前自动化测试执行了 AstrBot v4.29.0 的真实 QQ / 飞书 / WebChat 流式方法，网络和 UI 接口使用模拟对象；其他平台依据标准事件接口接入。平台自身的流式支持程度不由本插件改变。

## 两种匹配方式

检测词是**普通字符串，不是正则表达式**。多个词是“任意一个命中即可”。

| 设置 | 行为 | 首条消息何时发送 |
|---|---|---|
| `exact`（默认） | 回复在识别窗口内结束，去掉首尾空白后等于某一个检测词才拦截 | 排除检测词的可能性或超出窗口后，立即恢复流式发送 |
| `contains` | 开头识别窗口内包含完整检测词，就丢弃当前回复及其剩余分片 | 未命中时，超出窗口或生成结束后交给平台发送 |

这是一个短沉默标记识别插件。**超过 32 字符或 32 分片的识别窗口后直接放行，之后不再扫描正文。** 包含模式不会因为长回复末尾出现检测词而撤回或截断已经发送的内容，不承担全文条件过滤。可自行调整窗口；字符数按原始文本计算，包括空白，分片数包含空白分片，`None` 不计。

示例（默认词 `[NO_REPLY]`）：

| 模型输出 | exact | contains |
|---|---|---|
| `[NO_REPLY]` | 拦截 | 拦截 |
| 换行 + `[NO_REPLY]` + 空格 | 拦截 | 拦截 |
| `解释一下 [NO_REPLY] 的含义` | 放行 | 拦截 |
| `[NO_REPLY]。` | 放行 | 拦截 |
| `[NO_REPLY][SILENCE]`（列表里有这两个词） | 放行 | 拦截 |
| 32 个普通字符 + `[NO_REPLY]` | 放行 | 放行 |

精确模式指**一个检测词**，不把连续多个检测词视为一个词。附带图片、文件等实际内容的消息也不是“只有检测词”；引用和 @ 元信息不算实际正文。模式匹配的是最终送往适配器的可见文本，开启“显示思考内容”时，思考文字也可能成为正文；如果想保持精确模式，建议关闭思考内容显示。

## 配置

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `markers` | `["[NO_REPLY]"]` | 自定义多个词，空项忽略、重复项去重；首个词用于提示模型输出 |
| `match_mode` | `exact` | 下拉选择“只有检测词”或“包含检测词” |
| `ignore_case` | `false` | 可选 Unicode 大小写折叠 |
| `inject_prompt` | `true` | 自动注入沉默提示词，每次请求至多注入一段 |
| `system_instruction` | 内置中文提示词 | `{primary}` 替换为首个词，`{markers}` 替换为词列表 |
| `suppress_followups` | `true` | 命中后停止当前事件传播，阻断该事件的后续发送 |
| `max_buffer_chars` | `32` | 开头最多检测的原始文本字符数；非流式也使用该窗口 |
| `max_buffer_chunks` | `32` | 开头最多缓存的分片数量；只影响流式输出 |

例如可以把 `markers` 设置为 `["[NO_REPLY]", "[SILENCE]", "不予回复"]`。
检测词首尾空白会被去除，至少需要一个有效词。最多 4096 个词、总长度最多 131072 字符。不要配置过于常见的字词，否则包含模式会频繁拦截正常回答。

超出窗口时立即放行已缓存内容和当前分片，不再扫描后续正文；不会把普通长回复丢弃。完整检测词必须落在窗口内，检测词较长时应适当调大字符数上限。窗口是待判定内容的限制，不是总回复长度限制，也不是媒体二进制大小限制。上游异常或取消时，不发送尚未判定的缓存内容。

## 实现与性能

- 精确模式使用前缀树，检测状态跨分片保留；`[NO` / `_REP` / `LY]` 可以正常识别。遇到不可能匹配的正文后，直接透传剩余流。
- 包含模式使用稀疏 Aho–Corasick 自动机，失败链接处理重叠词，查找每段文本无需逐一遍历全部检测词。扫描时间随识别窗口内的文本长度线性增长（哈希字典访问按均摊计），窗口外直接透传。
- 配置不变时复用已编译的树；每个消息事件只创建独立游标与缓冲区，并发会话不共享匹配状态。
- 不使用正则，不新增网络请求，不追加一次模型判断调用。
- 通过 `on_llm_request` 包装当前事件实例的 `send_streaming`；在任何平台适配器消费分片之前过滤。确认有内容要发送后才启动平台流式方法，避免空卡片、空消息。卸载时恢复方法，不修改平台类或进程全局发送函数。
- 非流式请求通过 `on_llm_response` 拦截，`on_decorating_result` 再检查最终正文。

## 后续追加内容与范围

默认阻断命中之后、**同一个事件**的 `event.send()` / `event.send_streaming()`，并停止后续事件传播。关闭 `suppress_followups` 后，当前匹配到的回复仍被丢弃，但允许后续插件追加内容。

保护范围是 AstrBot 内置 AI 通过事件发送的回复。以下内容不在保护范围内：

- 插件或工具在命中之前已经独立发送的消息；这类消息无法撤回。
- 直接调用平台 API、`Context.send_message()` 或另建事件的主动发送。
- 第三方 Agent 执行器绕过 `on_llm_request` 的自定义发送链路。

开启“输出工具状态/工具结果”时，可能提前看到工具消息；这不表示沉默正文漏发。需要安静的体验可关闭这些输出开关。过滤器不会取消已执行的工具副作用。

本插件不自行写入或复制会话历史，避免与 LivingMemory 等插件重复写库。开启停止事件传播时，AstrBot 4.29 的内置逻辑可能跳过该次会话历史保存；这符合框架的停止语义。已经提前运行的记忆插件仍可能记录模型内容。

## 验证

```bash
python -m unittest discover -s tests -v
```

测试覆盖跨分片、多个词和前缀重叠、Unicode、随机输入与朴素算法对照、并发事件、正常流式即时性、窗口边界命中、超限放行、媒体、异常取消、提示词注入、停止传播与卸载恢复。

CI 在 Python 3.10 / 3.12 / 3.13 上运行，并下载固定版本 v4.29.0 的官方 QQ、飞书和 WebChat 适配器，执行其真实 `send_streaming` 方法。QQ 覆盖原生流式和回退发送；飞书覆盖卡片更新、工具分段及创建/发送失败回退；WebChat 检查空结束通知及正常输出。AstrBot 实际运行请使用其要求的 Python 版本。网络、UI 和其余框架部分使用模拟对象；**尚未在真实平台账号上进行端到端测试**。

本地性能样本：1000 个检测词、10 万字符、64 字符分片，自动机构建约 1.9 毫秒、扫描约 9.1 毫秒（Python 3.9.9，单次测量，仅供参考，不是跨机器性能承诺）。

安装后建议验收：

1. exact + 流式：只输出 `[NO_REPLY]` 时平台无正文消息，普通长回复仍按原先方式发送。
2. contains + 流式：在开头 32 字符 / 32 分片内输出完整检测词时不发送正文；正常长回复、窗口之后才出现检测词的回复应放行。
3. 设置第二个检测词并测试；关掉自动注入后确认原有人设保留。
4. 出现 `[NoReply] 已拦截当前回复` 时，确认同一事件的后续追加内容被丢弃。
